# Generated Compiler Bootstrap Overlay JAR

## Status

Implemented for all 31 bootstrap classes currently changed by Doppio's parsed
overlay dispatch. Difficulty: medium-high.

## Problem

Doppio loads a Java 8 `rt.jar` and applies parsed modern overlays immediately
before parsing selected bootstrap classes. This gives runtime bytecode and
reflection one real method table, but a hosted compiler does not discover those
methods by asking Doppio's already-loaded `ClassData`. Kotlin and Scala read
class files from their configured compilation classpaths. As a result, source
that directly calls an overlaid method can fail to compile even though the same
method is available when generated bytecode runs on Doppio.

The earlier workarounds pointed Kotlin at a host JDK through `-jdk-home` and
extracted `Duration` and `TimeUnit` from a host Java 17 `java.base.jmod` for
Scala. That proved the source was valid, but it also exposed host JDK metadata
that Doppio did not own.

The replacement is a generated, compiler-only JAR containing the Java 8
bootstrap classes changed by Doppio's parsed-overlay transformer. It presents
exactly the metadata Doppio will present at runtime without importing a host
JDK's API surface.

## Goals

- Use one parsed-overlay dispatch for runtime class loading and offline
  compiler metadata generation.
- Generate the overlay from the repository's Java 8
  `vendor/java_home/lib/rt.jar`.
- Package only class entries whose bytes actually change.
- Make clean rebuilds byte-for-byte deterministic and gate stale artifacts by
  content hash rather than modification time.
- Put the generated JAR before `doppio.jar` and `rt.jar` for Kotlin and Scala
  source analysis, including the main compiler, broad modern interop, and
  focused modern API suites, without adding it to Doppio's runtime bootstrap
  classpath.

This artifact is not a replacement JDK, a general Java 17 API signature JAR, or
a second implementation of modern methods.

## Artifact

The Grunt task `generate_modern_bootstrap_overlay` writes:

```text
build/modern-bootstrap-overlay/modern-bootstrap.jar
```

The artifact is generated build output and is not added to `jdk.json`, release
runtime listings, `JAVA_HOME`, or the normal Doppio bootstrap classpath. It
contains no copied resources, unchanged classes, directory entries, manifest,
host JDK classes, or Doppio helper classes. Helper and shim classes remain in
`vendor/java_home/lib/doppio.jar`.

## Shared Overlay Dispatch

`src/ClassLoader.ts` exports
`applyModernBootstrapOverlays(typeStr, data)`. The bootstrap loader calls this
function immediately after reading a class and before `defineClass`. The Grunt
generator imports the compiled function and calls it for every `.class` entry
extracted from Java 8 `rt.jar`.

The exported function is the only class-to-transform dispatch. The build task
does not use its expected 31-class postcondition as a selection list and does
not call individual overlay helpers. This keeps runtime metadata and
compiler-visible metadata synchronized when a parsed overlay is added,
removed, or reordered.

The transform has this contract:

- `typeStr` is a JVM reference descriptor such as
  `Ljava/time/Duration;`, not a binary name or path.
- `data` is the untouched class entry from the configured Java 8 `rt.jar`.
- an ineligible descriptor returns the original bytes unchanged;
- an eligible descriptor returns the fully transformed class bytes;
- malformed or unexpected Java 8 class structure is a hard error, not a
  reason to copy the original class into the output.

Parsed-overlay transforms are deliberately not required to be idempotent.
Several append methods or rename exact constants and would duplicate members
or fail if applied to their own output.

## Class And Descriptor Gates

The generator visits every regular `.class` entry extracted from the pinned
`rt.jar`, but eligibility remains inside the shared dispatch. For each entry
`p.class`, it derives `L${p};` after normalizing platform separators to `/`.
After transformation, an independent expected-set assertion requires the exact
31 changed class paths listed by the pinned baseline contract.

The initial Java 8 baseline has these descriptor gates:

| Entry gate | Descriptor gate |
| --- | --- |

| `java/lang/ref/Reference.class` | `Ljava/lang/ref/Reference;` |
| `java/lang/Class.class` | `Ljava/lang/Class;` |
| `java/lang/reflect/Executable.class` | `Ljava/lang/reflect/Executable;` |
| `java/lang/reflect/Constructor.class` | `Ljava/lang/reflect/Constructor;` |
| `java/lang/reflect/AccessibleObject.class` | `Ljava/lang/reflect/AccessibleObject;` |
| `java/lang/reflect/Annotated*.class`, except `AnnotatedElement.class` | descriptors beginning `Ljava/lang/reflect/Annotated`, except `Ljava/lang/reflect/AnnotatedElement;` |
| `sun/reflect/annotation/AnnotatedTypeFactory$Annotated*.class` | descriptors beginning `Lsun/reflect/annotation/AnnotatedTypeFactory$Annotated` |
| `sun/reflect/annotation/TypeAnnotation$LocationInfo.class` | `Lsun/reflect/annotation/TypeAnnotation$LocationInfo;` |

The two prefix rules are intentional dispatch rules, not broad package scans.
On the pinned Java 8 `rt.jar`, they select the five public
`java.lang.reflect.Annotated*` interfaces other than `AnnotatedElement` and the
five nested `AnnotatedTypeFactory$Annotated*` implementations. All other rows
are exact descriptor equality checks.

Within each selected class, overlay helpers continue to gate patches by exact
member name and JVM descriptor. For example, the `Duration` transform renames
the Java 8 private `toSeconds()Ljava/math/BigDecimal;` member before adding the
public `toSeconds()J`, and method-handle overlays distinguish overloads by
their full descriptors. A missing, duplicate, or structurally incompatible
member must fail the task. Matching only a method name is not sufficient.

## Generation Pipeline

The task performs these steps:

1. Require the configured Java 8 `rt.jar` and the compiled shared transformer.
2. Extract `rt.jar` into a fresh private work directory. No host `jmod`,
   `jrt:/` image, or `JAVA_HOME` classes are consulted.
3. Enumerate every extracted `.class` entry.
4. Derive its JVM descriptor, then call
   `applyModernBootstrapOverlays` once with the untouched bytes.
5. Compare input and output by byte content, not JavaScript object identity.
   Write only non-identical outputs to the staging directory.
6. Package the sorted changed-class paths directly, without recursively adding
   staging directories or an automatic manifest.

The changed paths are sorted before the JDK 17 `jar` tool packages them without
a manifest or directory entries. `--date=2000-01-01T00:00:00Z` fixes every
entry timestamp. The CI determinism smoke verifies the resulting archive bytes
instead of assuming the tool invocation is reproducible.

At least `java/lang/Runtime.class`, the three transformed
`java/lang/invoke/MethodHandle*` consumer classes, `java/time/Duration.class`,
and `java/util/concurrent/TimeUnit.class` are required outputs because the broad
and focused compiler smokes depend on their direct modern methods. More
generally, a test records the complete 31-class expected changed-entry set for
the pinned Java 8 baseline; changing that set requires an intentional
parsed-overlay review.

## Rebuild And Hash Gate

Modification times are not an acceptable freshness check. The task computes a
versioned SHA-256 input fingerprint over the exact `rt.jar`, compiled overlay
transformer, generator implementation, and deterministic archive settings. A
cache hit is valid only when both the stored input fingerprint and the stored
SHA-256 of `modern-bootstrap.jar` match the files on disk. Otherwise the task
recreates its private build directory and writes the artifact and hash metadata
again.

`ci/modern_bootstrap_overlay_smoke.sh` performs two independent forced clean
generations and compares the final JAR SHA-256 values. It then checks the stored
artifact hash, exact 31-entry count, canonical class-only names, and required
`Runtime`, `MethodHandle`, `MethodHandles`, `MethodHandles$Lookup`, `Duration`,
and `TimeUnit` entries. The generator itself compares the complete sorted
31-class set before packaging, so an added, removed, or unexpectedly unchanged
parsed overlay requires an intentional contract update.

A same-input hash mismatch fails CI and reports both hashes. The task must not
silently bless a newly nondeterministic output.

## Compiler Smoke Classpaths

The overlay is an input to compiler source analysis, not to the VM running the
compiler. Both compiler families use this precedence:

```text
modern-bootstrap.jar : doppio.jar : rt.jar
```

Kotlin's main compiler, modern interop, duration, diagnostic, bytecode shape,
bytecode runtime, MethodHandles, and record smokes pass `-no-jdk` and add those
three JARs, in that order, to the compiler's explicit target classpath along
with the fixture's Kotlin dependencies. They do not pass a host `-jdk-home`.
Scala's main compiler, modern interop, duration, diagnostic, core,
MethodHandles, record, and StackWalker smokes pass the same ordered trio to
`-javabootclasspath`; their ordinary `-classpath` continues to contain the
Scala library and fixture dependencies.

The smoke scripts must reject a missing generated artifact and make the order
visible in one variable rather than assembling it at multiple call sites. They
must not inspect or extract `java.base.jmod`, discover a host JDK image, or use
host Java 9+ class metadata as a fallback. Host `java` and `javap` may still run
the generated fixture and inspect its bytecode for native comparison; they are
not metadata inputs to the Doppio-hosted compilation.

`ci/check_compiler_bootstrap_consumers.mjs` statically protects all 16 migrated
compiler consumers. It requires the exact ordered classpath variables and
compiler flags, including the Kotlin record support-class suffix, rejects
missing consumer scripts, and rejects adding `modern-bootstrap.jar` to a
declared runtime classpath. Its unit test covers reordered paths, a missing
record support path, missing Kotlin and Scala flags, missing target/boot
classpath arguments, runtime contamination, and a missing consumer.

`doppio.jar` follows the overlay because transformed signatures can reference
modern shim, helper, or marker types supplied there. Java 8 `rt.jar` remains
last and supplies every unchanged bootstrap class.

## Why Runtime Must Exclude The JAR

Doppio's bootstrap loader already applies
`applyModernBootstrapOverlays` to classes read from its Java home. If
`modern-bootstrap.jar` were inserted into that runtime path, the loader would
select a pre-transformed class and apply the same transform again. Depending on
the class, this would append duplicate methods, repeat interface or annotation
changes, or fail an exact baseline-member check. Even an overlay that happened
to survive two passes would have unreviewed metadata.

Therefore `vendor/java_home/jdk.json` and runtime packaging remain unchanged.
The compiler JAR appears only inside the Kotlin/Scala compiler option that
controls source metadata. Generated programs run with the ordinary Doppio
runtime, which reads Java 8 classes and transforms them once.

## Relationship To Parsed Overlays

The generated JAR is a materialized view of parsed overlays. It does not add a
new compatibility mechanism:

- parsed methods, interfaces, signatures, annotations, and bytecode inserted
  by `ClassLoader.ts` become visible to compiler classfile readers;
- direct-call-only resolution in `ConstantPool.ts` is not materialized;
- custom reflection-table entries that do not alter class bytes are not
  materialized;
- new class-library classes are not copied from `doppio.jar` into the overlay;
- runtime behavior and native helpers continue to live in the existing runtime
  and modern class library.

This preserves the parsed-overlay rule that direct calls, reflection, and now
compiler discovery observe one classfile method definition. The generated JAR
is only the compile-time projection needed because Kotlin and Scala parse class
files independently of Doppio's runtime `ClassData`.

## Limitations

- The output is tied to the exact Java 8 `rt.jar` classfile shapes. Replacing
  that baseline requires rebuilding and reviewing descriptor/structure
  failures and the changed-entry set.
- The artifact exposes only parsed overlays. APIs supported by other runtime
  fast paths may remain invisible to source compilers until converted to a
  parsed overlay.
- The artifact is Doppio-specific. Its transformed bytecode can reference
  Doppio helper classes and is not a portable boot JAR for HotSpot or another
  JVM.
- The overlay intentionally does not expose the full API of any host JDK.
  Kotlin or Scala sources requiring an unsupported modern bootstrap API should
  fail during compilation rather than compile against accidental host
  metadata.
- The classpath overlay model cannot represent a modern module image or module
  descriptors. Compiler smokes remain classpath-based and target Doppio's
  Java 8 bootstrap layout.
- Applying the JAR as a runtime patch, merging it into `rt.jar`, or transforming
  it a second time is unsupported.

## Acceptance Gates

The implemented gates are:

1. Runtime loading and the Grunt generator call the same exported dispatch.
2. A clean generator run emits only the expected changed classes and a second
   clean run has the same SHA-256.
3. Re-running the task with unchanged content is a verified hash-cache hit;
   changing `rt.jar`, the transformer, or archive settings forces a rebuild.
4. Eight Kotlin compiler smokes use `-no-jdk` with
   `modern-bootstrap.jar:doppio.jar:rt.jar` precedence and no host JDK metadata.
5. Eight Scala compiler smokes use the same precedence through
   `-javabootclasspath` and no extracted host `java.base.jmod` classes.
6. The tested compiler bootstrap consumer checker locks the ordered paths,
   compiler flags, consumer inventory, and runtime exclusion for all 16
   migrated smoke scripts.
7. The broad Kotlin and Scala modern interop smokes compile a direct
   `Runtime.version()` call and guard its `invokestatic` bytecode, while the
   focused `Duration`/`TimeUnit` smokes guard all of their direct modern method
   descriptors. Every fixture runs on both HotSpot and the ordinary
   single-transform Doppio runtime.
8. Runtime configuration and release listings contain no reference to
   `modern-bootstrap.jar`.

The hash-cache hit, 31-entry archive check, TypeScript 6.0.3 and 7.0.1 RC
checks, full Java 9-26 runtime suite, and Kotlin 2.4.0 and Scala 2.13.18
compiler smokes all passed. On 2026-07-18, the broad modern interop smokes also
passed with the compiler-only classpaths and proved that `Runtime.version()` is
resolved from this generated overlay rather than host JDK metadata. The main

metadata isolation in 91 and 72 seconds, respectively. The focused Kotlin
MethodHandles and record smokes passed in 688 and 163 seconds; the focused
Scala MethodHandles, record, and StackWalker smokes passed in 137, 91, and 97
seconds. The Kotlin MethodHandles budget is 900 seconds with a 30-second forced
